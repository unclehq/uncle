# Supply Chain Attestations

## Overview

Attestations provide cryptographically-signed evidence that artifacts (like binaries, packages, or container images) were produced by a specific build process. This allows consumers to verify that what they're using came from your source code and build pipeline, not from a compromised intermediary.

Uncle and GitHub Actions support generating **SLSA provenance** attestations for your build artifacts. These attestations are machine-readable, portable, and based on open standards ([in-toto](https://in-toto.io/) and [DSSE](https://github.com/secure-systems-lab/dsse)), so they work across tools and platforms.

## What gets attested?

When you enable attestations, GitHub Actions cryptographically signs:
- **What was built** — the exact artifact (filename, hash)
- **How it was built** — the workflow file, branch, commit, and runner
- **Who built it** — the GitHub Actions runner identity (verified by GitHub)
- **When it was built** — the timestamp of the build

The attestation is tamper-evident: if anyone modifies the artifact or changes the build metadata, the signature becomes invalid.

## Enable attestations in your workflow

### 1. Add permissions

Add `id-token: write` to your workflow's top-level `permissions`:

```yaml
permissions:
  contents: read
  id-token: write
```

This permission allows the workflow to request an OIDC token from GitHub for signing.

### 2. Add an attest step

After building your artifacts, add the `actions/attest-build-provenance@v1` step:

```yaml
- uses: actions/attest-build-provenance@v1
  with:
    subject-path: 'dist/**/*.tar.gz'
    token: ${{ secrets.GITHUB_TOKEN }}
```

Replace `dist/**/*.tar.gz` with the glob pattern matching your artifacts.

### Complete example

```yaml
name: Build

on: [push, pull_request]

permissions:
  contents: read
  id-token: write        # ← Required for attestations

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Build artifacts
        run: |
          mkdir -p dist
          # ... your build commands ...
          
      - uses: actions/attest-build-provenance@v1  # ← Generate attestation
        with:
          subject-path: 'dist/**/*.tar.gz'
          token: ${{ secrets.GITHUB_TOKEN }}
```

## View attestations

### On GitHub

1. Go to your repository's **Actions** tab
2. Click on a completed workflow run
3. In the run summary, attestations appear in a dedicated section if they were generated
4. From a release, attestations are linked from the artifacts

### As a user verifying artifacts

Install [`slsa-verifier`](https://github.com/slsa-framework/slsa-verifier):

```sh
brew install slsa-framework/slsa-verifier/slsa-verifier
```

Then verify an artifact:

```sh
slsa-verifier verify-artifact my-app.tar.gz \
  --provenance-path provenance.json \
  --source-uri github.com/myorg/myrepo
```

The verifier confirms:
- The artifact matches the recorded hash
- The attestation is validly signed by GitHub
- The build happened in the repository you specified
- No modifications have occurred since the build

## Standards and compatibility

Attestations generated by GitHub Actions follow the **SLSA v1.0 specification**, which uses:

- **In-toto Statement Format** — the container format for attestation data
- **DSSE** (Dead Simple Signing Envelope) — the signing and verification envelope
- **SLSA Provenance Schema** — the specification of what build metadata is recorded

These are open standards used across the software supply chain ecosystem. Attestations generated in one system can be verified using tools from another.

## What to attest

Best practices:

- **Always attest final artifacts** — binaries, packages, container images
- **Use specific globs** — `dist/**/*.deb` not `dist/**/*` to avoid including partial or temporary files
- **One attest step per artifact type** if you build multiple formats
- **Keep the token as** `${{ secrets.GITHUB_TOKEN }}` — this is the correct credential

## Common patterns

### Multiple artifact types

```yaml
- uses: actions/attest-build-provenance@v1
  with:
    subject-path: 'dist/**/*.deb'
    token: ${{ secrets.GITHUB_TOKEN }}

- uses: actions/attest-build-provenance@v1
  with:
    subject-path: 'dist/**/*.rpm'
    token: ${{ secrets.GITHUB_TOKEN }}
```

### Conditional attestation

```yaml
- uses: actions/attest-build-provenance@v1
  if: github.event_name == 'push' && github.ref == 'refs/heads/main'
  with:
    subject-path: 'build/**/*.tar.gz'
    token: ${{ secrets.GITHUB_TOKEN }}
```

### Only on releases

```yaml
- uses: actions/attest-build-provenance@v1
  if: startsWith(github.ref, 'refs/tags/')
  with:
    subject-path: 'release/**/*'
    token: ${{ secrets.GITHUB_TOKEN }}
```

## Troubleshooting

**"Artifact not found"** — Check the glob pattern matches files that actually exist after the build step.

**"No attestation appears on GitHub"** — Verify:
1. The `id-token: write` permission is set
2. The attest step ran (check the workflow logs)
3. The workflow didn't fail before reaching the attest step

**Attestation verification fails** — The artifact may have been modified. Re-download it directly from the release or build artifacts and verify again.
