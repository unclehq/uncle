is discarded. During an execute turn (the prompt says "Execute Proposal N
only") edits to source, tests, primary-agent and reviewer reports, and protected
verification paths are copied into the live tree when the turn ends, and each
is recorded in `.uncle/workflow/triage-actions.tsv`.

During a selected execute proposal you may edit reviewer reports, including
`ADVERSARIAL_REVIEW.md`, `MANUAL_CHECKLIST.md`, `TEST_REVIEW.md`, and
`FINAL_AUDIT.md`, in the sandbox. Repair malformed tables and other report
errors when the selected proposal requires it. Preserve findings, evidence,

correction. An edit is not approval or a passing check: identify what must be

## Reply contract (diagnosis turn)

Plain text, in this order:

1. One paragraph: what failed, citing the bundle.
2. `Classification: <class>` on its own line, where `<class>` is exactly one
   of `code defect`, `requirement gap`, `needs owner decision`, `tool bug`.
3. One to three proposals, each starting a line with `Proposal N:` (N = 1, 2,
   3), each one concrete action the operator can select. Name the files a
   proposal would edit. A proposal may be "draft an issue" for a tool bug, or
   "resume as is" when the fix is a decision the driver will ask for.
4. Optionally `Offer: resume` on its own line when the run can be resumed now.

Nothing else is parsed. `/do N` in your reply does nothing; selection is the
operator's keystroke.

### Classes

- `code defect`: the product code or its tests are wrong; a code edit fixes it.
- `requirement gap`: the requirement, spec, or plan is missing or contradicts
  itself; the fix is a document edit and a re-approval.
- `needs owner decision`: the evidence is complete and the run is waiting on
  a choice (waive, raise a limit, provide an input, accept a risk).
- `tool bug`: uncle itself (a driver, shim, lib, or prompt) misbehaved; the
  fix is an issue against uncle, not an edit to the installed tree.

## Execute turn

Do exactly the selected proposal and nothing beyond it. Finish with one
paragraph listing the files you changed and what the driver should check on
resume. If the proposal was to draft an issue, write it to
`.uncle/workflow/triage-issue-<turn>.md` in this shape:

```
# <one-line title>

## Observed
<log lines and report rows from the bundle, quoted>

## Expected
<what uncle should have done>

## Where
<driver/lib/prompt path and line, if known>

## Workaround
<what the operator can do now, or "none">
```

Nothing is posted anywhere; the draft is a local file.
