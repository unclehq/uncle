### MC-201

- **Action:** Built an isolated sample project under /tmp/mc201.PDT0/proj (git repo, CHANGE_REQUEST.md and CHANGE_SPEC.md, stage fingerprints recorded for ANALYZE and PLAN with `revalidate.py record`). Changed CHANGE_SPEC.md so PLAN counted as changed. With the UNCLE_* variables cleared and the worktree's `uncle` run explicitly, invoked `uncle --revalidate --noui --attended` with stdin from /dev/null and stub claude/codex binaries on PATH. Observed the output, exit code and approvals. Submitted no approval.
- **Expected result:** Revalidation stops at the reopened gate with exit 75 and reports the stage as blocked. It neither approves the gate nor continues into downstream execution.
- **Actual result:** Did not reach any gate. The plan table printed ANALYZE reuse and PLAN run (changed: doc:CHANGE_SPEC). The runner then started scripts/change-workflow.sh, which rejected its argument: it printed 'Unknown argument: --noui' and its usage text, and exited non-zero without starting a stage. revalidate.py default_runner (scripts/lib/revalidate.py, subprocess.run(['bash', driver, '--noui'])) passes --noui to the driver, and the driver accepts only -h/--help/--version/--attended/--unattended. The final line was 'PLAN failed' and the overall exit was 1, not 75. No stage was reported as blocked. No approval files were written and no model stub was called. Running `bash scripts/change-workflow.sh --noui` directly gave the same 'Unknown argument: --noui' error. Because of this, a stage run through the real `uncle --revalidate` cannot reach a human gate. The 75-at-gate behaviour was exercised only with the driver called directly in the repo's own integration test, which I did not run here.
- **Defects:** New: default_runner passes --noui to change-workflow.sh, which rejects it as an unknown argument. Revalidation therefore exits 1 instead of stopping at the reopened gate with 75. Separately, this worker's accidental overwrite of .uncle/docs/CHANGE_SPEC.md in the real worktree must be repaired.
