# Test evidence handoff

This is a documentation reconciliation stage, not a repair stage. Do not edit application source, tests, dependencies, configuration, or the approved plan.

Read canonical test-review JSON, canonical updated-plan JSON, driver green-check evidence when it exists, and relevant existing tests. Re-run only targeted verification commands when needed. Never run the approved full Verification commands block here: that is the driver's one-time green check. Write `.uncle/workflow/documents/AUTOMATED_TEST_REPORT.json` as JSON only: `{"schema":"uncle.artifact/v1","kind":"automated-test-report","commands":[{"command":"...","status":"PASS|FAIL|BLOCKED|NOT RUN|N/A|DRIVER PENDING","output":"...","requirements":["..."]}],"coverage_gaps":["..."],"next_action":"..."}`. The driver validates and renders the Markdown view. When the green check has not happened yet, say `DRIVER PENDING` for that block rather than inventing an outcome.

`output` must be a non-empty string on every command, with no exception for a command that produced no stdout (e.g. one redirected to `/dev/null`): write a short factual note instead, such as `"(no stdout; command redirects its own output to /dev/null; exit 0)"`. Never leave it `null` or omit it -- a delivery with no `output` on any command is rejected.

For planned negative checks, record actual fail-then-pass evidence from a disposable copy, or NOT RUN and why. Do not infer coverage from an exit code. Replace the fallback placeholder; do not claim a check ran unless evidence says it did. Write the required concise `implementation-notes` JSON object to `.uncle/workflow/documents/IMPLEMENTATION_NOTES.json`, never to `.uncle/docs`, matching this shape: `{"schema":"uncle.artifact/v1","kind":"implementation-notes","notes":[{"topic":"...","detail":"..."}]}`. Both transport files must be JSON; Markdown is not an acceptable output here.
