# Defects

## New defect: closing_trailer's verdict parser (_SO_VERDICT in scripts/lib/change-pr.sh) does not recognise the application's emitted FINAL_AUDIT.md format (bare final line READY / READY WITH NON-BLOCKING ISSUES / NOT READY), so a finished change never gets 'Closes' and always shows 'audit verdict unavailable'. Not yet recorded in DEFECTS.md (worker may not edit it).

- **Status:** FAIL
- **Evidence:** Captured bodies came from running python3 -I /tmp/mc901/h.py. Fixtures: FINAL_AUDIT.md rendered by artifact_json.render_final_audit, e.g. '## Findings\n\nREADY\n' and a table row '| AR-3 | low | Issue #235 stays open until follow-up | Not stated | follow up | NO |' followed by 'READY'. IMPLEMENTATION_NOTES 'Acceptance delivery' tables (with and without the AC-2 BLOCKED row) and a VERIFICATION_REPORT 'Acceptance gate' table with MC-1 YES PASS. Per-case Still open results with origin: ready -> [audit verdict unavailable]; notready_override -> [override recorded, audit verdict unavailable]; rwnbi_blocked_AC2 -> [audit verdict unavailable, AC-2: required acceptance row BLOCKED]; ready_AR3 -> [audit verdict unavailable, AR-3: audit finding: issue stays open]. All four originless bodies end with the closing ``` of the attestation block. scripts/lib/change-pr.sh _SO_VERDICT (about line 485) and scripts/lib/artifact_json.py:328-332 (render_final_audit appends the bare verdict) are the two sides of the mismatch. Limitation: the full handoff() was not run end to end; only its assembly lines were exercised with the mocks listed above.
- **Expected result:** READY case ends with 'Closes owner/repo#123'. Unfinished cases contain 'Refs owner/repo#123' and a nonempty Still open list naming the applicable reasons and blocker IDs, with no closing trailer. The attestation precedes the trailer. The originless case has neither trailer nor Still open section.
- **Actual result:** Partly met. The originless cases are correct: no trailer and no Still open section in all four. The attestation precedes the trailer, and the NOT_READY+override, AC-2 and AR-3 cases give Refs with the right reasons. The finished READY case is wrong. With the emitted audit (bare final line 'READY') it produced 'Refs owner/repo#123 / Still open: - audit verdict unavailable' instead of 'Closes owner/repo#123'. The cause is _SO_VERDICT in closing_trailer, which requires the word 'verdict' followed by ':' or '-'. The emitted format has no such line, so every real audit is read as 'verdict unavailable' and the issue never auto-closes. The other cases carry the spurious 'audit verdict unavailable' entry too: the override case lists 'override recorded' and 'audit verdict unavailable' but not 'audit verdict not ready', and the AC-2 case lists 'audit verdict unavailable' and 'AC-2: required acceptance row BLOCKED'. scripts/tests/pr-closes-refs-test.sh only passes because it uses a hand-written 'Verdict: READY' line.
