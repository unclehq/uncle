Seeded from [unclehq/uncle#233](https://github.com/unclehq/uncle/issues/233).

Omitted sections: Schema/persistence (journal gains none new beyond existing keys), Migration (none), Concurrency (single driver process), Feature flag (none; gated by existing hand-off mode and envelopes presence), Observability (reuses attest's existing prints).

Issue 233

## 1. Selected technical approach

D-1: add a driver action `attest-handoff` in the embedded Python of `scripts/lib/change-pr.sh` (`main()` ~1860 beside `commit-tree`). It is the single authoritative writer of `gate_publication` on the hand-off attestation. It: `j=load()`; if `envelopes_enabled()`: (a) take the audited tree from the persisted journal first: if `j.get('audited_tree')` is set, set `j['commit_tree']=j['audited_tree']` in memory before calling `attest(j)` (idempotent rerun, SI-5), so a rerun never re-derives audited_tree from an already-attested tree; (b) record the prior bytes of any existing `.uncle/attestation.*` files so a failure can restore them; clear `release_skipped` on the in-memory journal (`j['release_skipped']=''`) so the hand-off never honors an operator's publish-anyway instruction (AR-013; the hand-off has no operator gate that could have recorded one legitimately): any blocking reason raises AttestationError and the hand-off fails; (c) call `attest(j)`, which rewrites `.uncle/attestation.*` from the in-memory state on every run (never skipped because they exist); (d) set `j['attestation']=sealed_attestation(j)` then `gate_publication=HANDOFF_GATE_TEXT`, one shared constant equal to exactly 'handoff (published by the host)' (lowercase), also used as the Statement approvals entry's approved_by in D-3; (e) `save(j)` only after both attestation files have been written and all in-memory journal fields are final, so a crash or failure before save leaves the old journal intact and a rerun repeats (a)-(e) from the old audited_tree. Failure handling: on any exception after attest() began writing (AttestationError, or any other exception from attest, sealing or save), the action removes the `.uncle/attestation.*` files it wrote (restoring prior bytes if they existed), leaves the journal unsaved, and exits non-zero: AttestationError exits 3 with `PR pending: Attestation blocked: ...`; any other exception exits 1. Rerun semantics (AR-005): a rerun re-attests, so the Statement's run fields (e.g. run id, timestamps) and the signature may differ from the first run; only `audited_tree` and the attested `commit_tree`/`tree` are guaranteed stable across reruns, and tests assert only those. Else (no envelopes): do nothing (summary path unchanged).
D-2: hand-off branch (:207) runs `change_pr_python attest-handoff` (the existing wrapper around `pr_code`, ~:2022) before `handoff_export.py`; on any non-zero exit (3 or 1) sets `CHANGE_PR_EXTRAS_REASON=handoff-failed`, returns 1, and never runs the exporter, so no `handoff.json` is written.
D-3: `consent_entry` returns, when `UNCLE_PUBLISH_MODE=handoff`, an entry `{gate:'publication',required:True,approved_by:'handoff (published by the host)',delegated_by:'',approver_kind:'host-handoff',human:False,digest,timestamp}`. The entry must carry an explicit non-human marker (`human:False` plus `approver_kind:'host-handoff'`) so that no consumer can read it as a human approval; the `approved_by` text alone is not the marker. The Statement's approvals must contain exactly one entry with gate 'publication'. Implementer first confirms in envelope.py/uncle-verify.py (read only) that approved_by is free-form and that these extra fields are accepted, and how verify reports the entry (expected: 'not human-approved'). If verify rejects the extra fields, keep `approved_by:'handoff (published by the host)'` with the marker carried in `delegated_by:'host-handoff'`; never fall back to 'operator' or any human-looking approver, and record the outcome in IMPLEMENTATION_NOTES.md. Tests assert: exactly one publication approvals entry; it carries the non-human marker; its approved_by and the sealed `gate_publication` both equal 'handoff (published by the host)'; and `uncle-verify.py` accepts it.
D-4: `handoff_export.py` unchanged in tree selection (already reads `commit_tree`, now the attested tree); add `audited_tree: journal.get('audited_tree') or tree` to `handoff.json`; the export uses the journal `attestation` as-is and must NOT re-stamp `gate_publication` (remove the unconditional overwrite at handoff_export.py:97). The fallback `attest.seal(...)` path, used only when the journal has no attestation (no-envelope journals), stamps `gate_publication='handoff (published by the host)'` itself so the exported field equals the sealed one. `changes()` needs no special case.
D-5: docs update.

D-6 (journal phase exclusivity): on success `attest-handoff` sets `j['phase']='handoff-attested'` in the same final `save(j)`. It never sets 'prepared', so the `phase=='prepared'` branch (~:1772) is not entered for a hand-off journal. Normal publish refuses when `j['phase']=='handoff-attested'` with exit 3 `PR pending: this change was handed off to the host; rerun the final audit to publish normally`. `attest-handoff` refuses (exit 1, handoff-failed) when the phase is 'prepared' or later (normal publish already begun); it is allowed on an unset phase or on 'handoff-attested' (idempotent rerun). A test asserts both directions: normal publish after hand-off refuses, and hand-off after a prepared journal refuses.
D-7 (rerun determinism, AR-020): `attest-handoff` derives its input tree deterministically on every run. If the journal has `audited_tree`, it first sets `commit_tree = audited_tree` and then runs attest(), so attest()'s `audited_tree = commit_tree` assignment re-stores the same value and a failed or partial earlier run can never promote an attested tree to audited_tree. The attestation files are rewritten from that tree on every run, and the journal is saved only after both files are written. After any run (first, rerun, or rerun after an induced failure) the invariant is: `audited_tree` equals the originally bound tree, and `commit_tree` is the attested tree. Tests cover success, rerun, and rerun after induced failure.
D-8 (failure ordering, AR-011): `attest-handoff` completes attest() and writes both attestation files, then calls save(j) as its last step; the exporter runs only after the action exits 0, so the journal is always saved before `handoff_export.py` starts. Any failure in the action (AttestationError, any other exception, or save(j)) or in the exporter makes the hand-off branch set `CHANGE_PR_EXTRAS_REASON=handoff-failed` and return 1, with no `handoff.json` left behind. A failed export leaves a saved attested journal; rerunning `attest-handoff` is safe (D-7) and then re-runs the exporter, repairing the state.
D-9 (envelopes_enabled): `envelopes_enabled()` is true when the envelopes manifest exists, as in the normal publish path; it is not true merely because the directory has contents. attest() then requires `.uncle/workflow/envelopes/` to be a directory and `load_envelopes` to succeed. If the directory is present but empty, missing, or unreadable, attest() raises AttestationError and attest-handoff exits 3, so the hand-off branch sets `handoff-failed`, returns 1, and writes no `handoff.json`. Only a journal with no envelopes manifest at all takes the no-envelope path (summary path unchanged; phase not set). Test row (in handoff-export-test.py, with the AC-6 cases): an envelope-enabled fixture whose envelopes directory is empty must exit non-zero with the attestation-blocked message and leave no `handoff.json`.
D-10 (transport integrity): `handoff.json` is an unauthenticated transport. Its `tree`, `changes` and `attestation` fields are convenience data and the host must not trust them alone. The stated detector for a tampered tree or changes list is `uncle verify --tree <commit>` run on the commit the host created by applying the hand-off: it recomputes the artifact digest from the applied tree and checks it against the attested Statement (and signature when signed). A mismatch or missing attestation is a verification failure and the host must not open or merge the PR. No new code is added for this; a test (AC-1 traceability) applies a deliberately altered `changes` entry and asserts the verify step reports the mismatch.

## 2. Alternatives considered
- Export script adds the files itself: duplicates Statement/sign logic; rejected.
- Move attest to bind: changes normal path and consent semantics; rejected.
- Call `attest` from bash by sourcing: not possible, logic lives in embedded Python.

## 3. Why preferred
Reuses `attest()` unchanged, so body and Statement come from one state and refusal behavior is identical.

## 5. Not to modify

`attest()` body, `snapshot()`, `uncle-verify.py`, `envelope.py`, `stagegate.sh`, `.gitignore`. The normal publish path in change-pr.sh is not modified except for one minimal guard that refuses a normal publish when the journal phase is 'handoff-attested' (D-6, owned by step 2, tested in step 4). Any verifier or envelope change needed for the hand-off approvals marker is out of scope and deferred.

## 6. Data flow
bind -> (new) attest-handoff writes `.uncle/attestation.*`, moves `commit_tree`, saves journal -> handoff_export diffs base..attested tree.

## 8. Interface changes
New internal driver action `attest-handoff`; `handoff.json` adds `audited_tree`.

## 10. Compatibility

No-envelope journals skip the action; additive JSON field; existing consumers ignore unknown keys.

Security note: integrity of a hand-off is established by `uncle verify --tree` on the applied commit, not by `handoff.json` fields; consumers must not treat `tree`, `changes` or `attestation` in `handoff.json` as authoritative.

## 12. Error and recovery

Empty or unreadable envelopes directory (manifest present): attest() raises AttestationError, attest-handoff exits 3 with `PR pending: Attestation blocked: ...`, hand-off maps it to `handoff-failed`, and no `handoff.json` is written.

Rerun after failure (AR-020): a failed or partial attest-handoff (AttestationError, or a failure after the attestation files were written but before save) leaves the journal's `audited_tree` and `commit_tree` as they were before that run. A rerun restores `commit_tree = audited_tree` when `audited_tree` is set, re-attests, and ends with `audited_tree` unchanged and `commit_tree` the attested tree.

AttestationError -> exit 3 `PR pending: Attestation blocked: ...`; any other exception in attest-handoff -> exit 1; the hand-off branch maps both to `handoff-failed` and does not run the exporter. On any failure the action removes the `.uncle/attestation.*` files it wrote (restoring prior contents) and does not save the journal, so no stale attestation files or half-updated journal remain. A NOT READY / blocking-policy reason always fails the hand-off: `release_skipped` is ignored (cleared in memory) so the 'publish anyway' branch of attest() is never taken in hand-off, even if the journal carries a stale `release_skipped`. Signing failure falls back unauthenticated inside attest (existing). Rerun is idempotent (D-1) while the phase is unset or 'handoff-attested': on rerun the action restores commit_tree from the journal's audited_tree (if set), rewrites both attestation files from that tree, and saves the journal only after both are written. `audited_tree` and the attested tree are identical across success, rerun, and rerun after an induced failure; the Statement run fields and signature may change on rerun, and that is not an error (tests assert only audited_tree and tree stability). A journal in phase 'handoff-attested' makes a later normal publish refuse, and a journal in 'prepared' or later makes attest-handoff refuse (D-6); both exit non-zero without writing files or changing the journal.

Failure ordering (AR-011): journal save precedes export. If the exporter fails after a successful action, the journal and attestation files are already consistent and a rerun repairs it. If save(j) fails after the files are written, the action exits non-zero (handoff-failed, exit 1) and a rerun rewrites the files from the same audited_tree. Every non-zero exit from the action or exporter maps to `handoff-failed`; the exporter never runs after an action failure.

## 14. Rollback

Revert the change-pr.sh, handoff_export.py, docs and test edits. Leftover `.uncle/attestation.*` regular files in a working tree are ignored by non-attested flows (they are excluded from snapshot()). A symlink at either path is never written through: attest-handoff refuses it, so rollback leaves no file outside the repo modified; an operator-created symlink is left in place for the operator to remove. Journals saved with attested `commit_tree` and `audited_tree` remain loadable.
